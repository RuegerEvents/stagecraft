# stagecraft-gdtf: decisions

Choices made where the GDTF 1.2 spec (DIN SPEC 15800) or the task left room. Kept
here while the crate is built outside the workspace; fold into
`docs/spec/decisions.md` when it joins.

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Package | Own `[package]` (edition 2024, MIT), no workspace inheritance, own `Cargo.lock`, no StageCraft dependencies. | Builds standalone while another agent edits the workspace; joins by removing it from `exclude` (then drop the lock file). |
| 2 | Units in types | Parsed types keep the XML units (metres, degrees, W, kg) and say so in field names (`length_m`, `beam_angle_deg`). Meshes, instances and silhouettes are in mm. | The data mirrors the file; everything that feeds geometry uses StageCraft's mm. |
| 3 | Axes | GDTF axes everywhere: x right, y away from the viewer, z up, fixture hanging, beams along −z. | This is the MVR fixture-local frame, so callers place meshes with the MVR matrix alone. |
| 4 | Matrices | Rows as written, translation in the 4th column (spec). If the 4th column is zero and the 4th row carries a translation, it is moved (old exporters). 3-row and 3×3 matrices are padded with identity. Unreadable → identity + warning. | Tolerance; the spec text is explicit about column-major meaning. |
| 5 | Tolerance | Only a missing/broken zip, a missing `description.xml`, malformed XML or a missing `<FixtureType>` fail. Everything else is a `Warning` (context + message). Trailing NUL bytes and junk after `</GDTF>` are cut (six real files had NULs). Decimal commas are accepted. Model and geometry names match ignoring surrounding whitespace (Astera writes `"Pixel 16 pix "`). | Real manufacturer files are messy; parse what we can. |
| 6 | Weight / leg height | `0` (the spec default) reads as `None`. | A zero weight would silently vanish from load sums. |
| 7 | Power | `power_w()`: sum of `<PowerConsumption>` if present, else sum of beam `PowerConsumption` **attributes actually written** (the spec default 1000 W per beam is not counted). | Avoid inventing 1000 W for every LED pixel. |
| 8 | Footprint | Per break: the highest slot used. Mode root = the mode's `Geometry`; channels on geometries in that tree keep their offsets; channels on a template are repeated per `GeometryReference` at `DMXOffset + Offset − 1`; `DMXBreak="Overwrite"` takes the reference's last `<Break>`; a missing matching `<Break>` means offset 1 (warning). Channels on geometries outside the mode tree are placed as written (warning). | Spec text plus what GDTF Builder produces. Verified: footprints equal GDTF Share's reported footprints for all 16 modes of 5 downloads, and datasheets for Spikie, Esprite, LEDWash 600, T-PIX 12. |
| 9 | Nested references | References inside a template are expanded for meshes and names, but their offsets are not added to the outer reference's. | GDTF defines no nested DMX offsets. |
| 10 | Reference instances | An instance takes the reference's name, position and (optional) model; the template's own `Position` is ignored; its kind (e.g. `Beam`) is kept. | Spec: the reference describes the instance; templates are usually at identity. |
| 11 | Mesh file choice | Lookup order glTF then 3DS (`gltf`, `3ds`; for `Lod::Low/High` first the `_low`/`_high` folders). Case-insensitive; a `File` with extension is accepted. Missing or broken file → primitive + warning. | Spec prefers glTF. |
| 12 | glTF axes | GLB is read as y-up and turned to z-up: (x, y, z) → (x, −z, y). Node transforms applied. Checked on Robe and Vectorworks files: extents then match the model dimensions. | glTF convention; GDTF Builder exports this way. |
| 13 | Wrong up axis | If the model dimensions fit the other up-axis reading clearly better (shape error < ½ and > 0.3), the mesh is turned and a warning added. | Cheap guard against exporters that ignore the glTF convention. Never triggered on the real files. |
| 14 | Scaling | Scaled about the mesh origin (not recentred) to Length × Width × Height. Axis with dimension 0: mean scale of the others. No dimensions: glTF read as metres, 3DS as mm (metres if smaller than 10 units). | Spec rule; origin is the suspension point. |
| 15 | Wrong dimensions | If one axis already matches the dimensions in m or mm (±1 %) but another would stretch by more than 25 %, the mesh keeps its proportions at that unit (warning). | Vectorworks "Custom@" files write Width = Height = diagonal; strict scaling made a Robe T1 718 mm deep. Now 400 × 294 × 736 mm, matching the datasheet. |
| 16 | Primitives | Generated (box, cylinder, ellipsoid, yoke U, scanner, conventional), not the spec's reference 3DS meshes, which carry no licence. Placement copied from those meshes: GDTF 1.0 types (`Base`, `Yoke`, `Head`, `Scanner`, `Conventional`) and `Cube`/`Cylinder`/`Sphere`/`Pigtail` centred; `Base1_1`, `Scanner1_1`, `Conventional1_1` hang below the origin. `Conventional` (1.0) lies along y, `Conventional1_1` along z. `Undefined` without a file → box. | Licence; same bounding boxes as the references. |
| 17 | Normals | glTF normals kept when every primitive has them; otherwise flat normals (vertices unwelded). 3DS always flat (smoothing groups ignored). | Simple and correct shading for low-poly fixture meshes. |
| 18 | Silhouette | Convex hull per part plus one for the whole fixture, top view, mm, CCW. | Per-part hulls keep yoke arms and pixel rings readable; a true union outline can come later. |
| 19 | SVG | Raw bytes per model and view (`models/svg`, `svg_side`, `svg_front`); `plan_svgs()` lists top views with each instance's transform. No SVG composition here. | Plan symbols are assembled by the plan code. |
| 20 | Share HTTP | `ureq` 3 (blocking, rustls), cookie jar in the agent, 120 s timeout, 512 MB body limit. Errors from `downloadFile.php` arrive as JSON with HTTP 200, so a download must start with `PK`. | Small dependency; the app calls it from a worker thread. |
| 21 | Share cache | `<cache>/list.json` (raw answer, age from file mtime), `<cache>/files/<rid>.gdtf` (never stale: a rid is one revision). A failed refresh falls back to a stale list. | Offline use; rids are immutable. |
| 22 | Share list parsing | Field by field from `serde_json::Value`, numbers accepted as strings and vice versa; entries without `rid` dropped. | The live list mixes types (`rating` is a string). |
| 23 | Keychain | Feature `keychain` (macOS): account from an attribute search via `security-framework`; the secret via `/usr/bin/security find-generic-password -w` (captured, never echoed), the framework read only as fallback. | Reading the secret through the framework opens an "allow access" dialog for every newly built binary, which hangs unattended runs; `security` is on the item's access list. |
| 24 | Live test | `share_live` is `#[ignore]` and downloads into `testdata/private/gdtf/` (cache in `.share-cache/` there). | Network and credentials. On this machine LuLu holds new binaries' connections until allowed, so the first live run was done with an equivalent Python script (same endpoints, same cache layout); `share_cache` then exercises the Rust client offline on that real data. |
