# Decisions

Choices made while building, where the spec did not say. Add a row when you make one.

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-11-17 | Undo | Undo keeps whole document versions. The document uses `imbl` persistent maps, so a version costs only the changed nodes. | Simple and always correct, no inverse operation per command. |
| 2026-11-17 | Command registration | Explicit list in `registry.rs`, no `inventory`. | `inventory` is unreliable on WASM. |
| 2026-11-17 | Geometry in the API | Points are plain `[f64; 2]` / `[f64; 3]` in mm; `glam` only inside computations. | JSON schemas stay simple for AIs. |
| 2026-11-17 | MCP shape | Three tools (`commands`, `describe`, `execute`) instead of one tool per command. | Hundreds of commands would flood an MCP client's tool list. FilmCraft uses the same shape. |
| 2026-11-17 | Discovery | A running instance writes `instances/<pid>.json` (port, token, file) into the app data dir; MCP finds it there. | FilmCraft's control channel cannot be found from outside; we avoid that. |
| 2026-11-17 | Async | Control server on plain `std` threads and channels, no tokio. | Small, and the engine is single-owner anyway. |
| 2026-11-17 | Test data | Real MVRs live in `testdata/private/` and are git-ignored. | They are client projects. |
| 2026-11-17 | UI language | English UI, i18n catalog from the start (user). | User choice. |
| 2026-11-17 | Theme | Light and dark, follows macOS, switchable (user). Sheets always white. | User choice. |
| 2026-11-17 | Truss 3D | Real chords and diagonals, simpler level of detail when zoomed out; 2D double line with diagonals (user). | User choice. |
| 2026-11-17 | Overnight order | Blocks in roadmap order; parallel worktrees where independent: 2 → 3 → (4 ∥ 5 ∥ 6) → (7 ∥ 8) (user: roadmap order, parallel allowed). | User choice. |
| 2026-11-17 | Title block | Generic with placeholders, company/logo from document settings (user). | User choice. |
| 2026-11-17 | Typed dimensions | While drawing, a plain number is metres ("4.5" = 4.5 m); `mm`/`cm`/`m` suffixes work. Tab switches to the angle (degrees, default: towards the pointer). Inspector and table fields are mm (with optional `m` suffix). | The spec's example "type 4.5" means metres; data fields stay in the model's unit. |
| 2026-11-17 | Navigation | Mouse wheel (line units) zooms at the pointer; trackpad scroll (point units) pans; pinch and ⌘-scroll zoom; middle-drag or Space-drag pans. | Matches both input devices without a setting. |
| 2026-11-17 | Box selection | Left-to-right = window (fully inside), right-to-left = crossing (touching). | CAD convention, as in Vectorworks/AutoCAD. |
| 2026-11-17 | Pick priority | Under the pointer: fixtures before truss before walls before floors, then nearest. | Small things sit on big things; a click on a floor area should not hide what stands on it. |
| 2026-11-17 | Snap order | Endpoint, midpoint, truss axis (distance along rounded to the grid), grid (100 mm default). Shift locks horizontal/vertical from the last point and aligns with nearby object points. | Object snaps beat the grid; truss positions stay on round numbers. |
| 2026-11-17 | Tag visibility | Per view (UI state, `ui.set_tag_visible`), not in the document. An object is hidden if any of its tags is hidden; untagged objects always show. Layer visibility stays in the document. | Spec: visibility per view by tags. Hiding "light" should hide a fixture also tagged "front". |
| 2026-11-17 | New truss height | The truss tool draws at 6000 mm above the layer by default (tool option). Fixtures clicked onto a truss hang at the profile's half height below its axis; elsewhere they stand on the layer at z 0. | Plan drawing has no z; a hung truss is the common case. |
| 2026-11-17 | New objects | Go on the active layer (●, `ui.set_active_layer`), or the first layer. A created object is selected. | So the inspector shows it right away. |
| 2026-11-17 | Inspector multi-edit | A field shows a value when all selected agree, else "mixed"; an edit applies to all as one `batch`. Absolute position edits apply to objects whose parent is not selected (children follow). FID for several fixtures numbers them (`fixture.number`) in plan order. | FIDs must stay unique; moving parent and child both would double the move. |
| 2026-11-17 | Table order | Fixtures with a FID by FID; the rest in plan order (x, then y). Cell edits on a range apply to every cell; fill series counts from the first cell, with the step from the first two when both are filled; addresses roll over universes. | A patch list reads by FID; plan order is stable while numbering. |
| 2026-11-17 | Fixture plan symbol | Generic 260 × 340 mm box with a lens edge at local +y and the FID inside, until block 5 brings GDTF/SVG symbols. | Something readable at plan scale. |
| 2026-11-17 | Truss catalogue | Built-in JSON in `stagecraft-geom/catalog/` (F24, F31–F34, F44P, X30D/V, H30V, H40V; nominal sizes, typical kg/m). Unknown profile names draw as an F34-sized box. User catalogues come later. | Spec: catalogues are JSON; numbers checked against maker data later. |
| 2026-11-17 | Fonts and icons | Roboto vendored (Apache 2.0, copied from grandPA); arrows/crosses painted, as Roboto lacks them. | Same look on every machine and in headless PNGs. |
| 2026-11-17 | Kind updates | Added `floor.update`, `wall.update`, `truss.update` to core. | The inspector and the table need command paths for kind parameters. |
| 2026-11-17 | Mesh detail | `Lod` is `Full` (truss chords, diagonals, end frames), `Simple` (chords only), `Box` (outer box). Only truss differs; other kinds ignore it. Meshes depend on kind parameters and `Lod` only, never on placement, so views cache them per object. | User: real chords and diagonals, simpler when zoomed out. |
| 2026-11-17 | Mesh layout | Flat faces get their own vertices (sharp normals); a mesh carries material groups (`Group`) instead of one class, so a fixture has body and lens. Watertight = every edge (by position) used equally often in both directions, so touching closed parts (braces at a node) count. | Sharp edges read better on CAD geometry; GDTF models will need several materials too. |
| 2026-11-17 | Truss mesh | Axis along local x through the centre of the section; three-chord profiles stand on two chords, apex up; diagonals ≈ 40 % of the chord Ø, one bay per face width, zigzag phase alternating per face; braces end on the chord surface. | Matches the plan symbol and common 3-point truss rigging. |
| 2026-11-17 | Fixture placeholder | Until GDTF (block 5): yoke bar, body 260 × 340 × 250 mm, lens cylinder at local +y. GDTF convention: origin = hanging point, the body hangs below (−z). The fixture tool turns floor fixtures over (rotation x 180°); the demo does too. | MVR/GDTF put standing fixtures upside down the same way; block 5 then needs no conversion. |
| 2026-11-17 | Wall rings | A wall path whose last point meets the first closes into a mitred ring. | A room outline drawn as one wall should not get a seam with end caps. |
| 2026-11-17 | Section planes | A `Plane` hides the side its normal points to. Plane coordinates: `v` = world up projected into the plane (world +y for horizontal planes), `u = v × n`, so a viewer on the hidden side sees u right, v up. Cut loops: outers counter-clockwise, holes clockwise; holes by nesting. Cap triangulation with `earcutr`. | One convention for the 3D clip, cut faces now and vector sections in block 6. |
| 2026-11-18 | 3D rendering | The paint callback renders into its own offscreen target (4× MSAA, Rgba8UnormSrgb, Depth32Float, reversed depth) in `prepare` and blits it into egui's pass in `paint`. | Independent of eframe's depth/MSAA settings and identical in the headless test renderer, so screens show real 3D. Reversed depth keeps a whole venue free of z-fighting. |
| 2026-11-18 | 3D navigation | Left-drag orbits, right/middle/Shift/Space-drag pans, mouse wheel and pinch zoom at the pointer, two-finger trackpad scroll orbits (Shift pans). A click without drag selects (Shift toggles). Orbit is turntable (z stays up). | Orbit is the common act in 3D; plan keeps scroll = pan. Turntable suits buildings better than a free trackball. |
| 2026-11-18 | 3D look | Camera-relative key light (upper right) + sky term + headlight; flat colours per material class and theme; two-sided lighting with darker inside faces; a ground grid 1 mm below layer 0 that floors cover. Cut faces red with screen-space hatching (or solid via `ui.section {hatch:false}`). | Every standard view reads without setting up lights; cut faces stand out in both themes. |
| 2026-11-18 | Standard views | Front looks from the audience (−y) upstage, side from stage right (+x), iso from front right above (yaw −45°, pitch 35.3°). `ui.camera {view}` fits unless eye/target are given or `fit:false`. The orthographic view shows what perspective shows at the target's depth. | Spotlight users expect front = audience view. Keeping size when switching projection avoids jumps. |
| 2026-11-18 | Section planes | `ui.section {axis}`: x hides stage left of the offset (+x side), y hides downstage (look from the audience at the cut), z hides above (a plan cut). Default offset: model centre. `flip` turns it round; `normal`+`origin` for a free plane; `box` hides outside six planes (default: model bounds a tenth in from each side in plan, full height). Cut faces are computed on the CPU per object and cached until geometry or planes change. | The commonest sections in theatre: plan cut, centre-line section, cross section. CPU cuts are reused for vector sections in block 6. |
| 2026-11-18 | Truss detail in 3D | Full when the profile is ≥ 9 points wide on screen, Simple ≥ 2.5, else Box; more than 400 truss pieces in view cap at Simple, more than 2000 at Box. | Diagonals are noise when they are a pixel wide, and cost the most triangles. |
| 2026-11-18 | Split view | Plan left, 3D right, 50/50; ⌘1/⌘2/⌘3 for plan/3D/split; `ui.zoom_to_fit` fits whichever views are shown. | Simple and predictable; a draggable divider can come later. |
| 2026-11-18 | Catalogues | Built-in catalogues live in `stagecraft-core/catalog/*.json` (truss profiles, platform systems, supports), embedded at compile time; `stagecraft-geom` re-exports them. Users extend them with files of the same shape in `<data dir>/StageCraft/catalog/*.json` (macOS: `~/Library/Application Support/StageCraft/catalog/`, or `$STAGECRAFT_HOME/catalog/`), loaded by the app at start; an entry with a built-in name replaces it. `catalog::extend(json)` does the same without files (wasm). | Load sums in core need kg/m; the core stays file-free and wasm-clean. |
| 2026-11-18 | Load sums | `load.report` sums only: own weight (catalogue kg/m and node kg for truss, bar kg/m for battens, kg/m² for platforms, 0.55 kg/m² velour for curtains and 0.32 kg/m² molton for masking, given kg for fixtures, hoists, supports) plus everything attached below, recursively. Rows per truss piece, run (its pieces and nodes are its own weight), batten and hoist; batten max load and hoist capacity compare against the attached load. Fixtures without `weight_kg` count as 0 and are reported as unknown. No distribution between several hoists. | Spec: sums only. A shared truss is attached to one hoist; splitting needs statics, later. |
| 2026-11-18 | Truss runs | One `truss_run` object per run with pieces and nodes as children (no connection detection). `truss.run` builds it from points: corners (`truss_node`) at bends, pieces split into the profile's stock lengths (longest first, a rest becomes a custom piece); `truss.join` groups existing pieces. Nodes reach one profile width from their centre along each arm; arms are horizontal directions plus optional down/up. Run bends are horizontal only. | Explicit grouping survives moves and edits without guessing which ends touch; load per run falls out of the tree. |
| 2026-11-18 | Node presets | `corner_90`, `corner_45` (arms 45° apart), `corner_135` (the run turns by 45°), `tee`, `corner_3way` (two horizontal arms + down), `cross`, `tee_4way` (T + down). | Covers the 2-, 3-, 4-way 90°/45° corners of the common systems. |
| 2026-11-18 | Curtain states | A curtain has `opening` 0–100 % and `gather`: `tab` (sideways on a traveller, alias `greek`) or `italian` (bunched up diagonally to the upper outer corners). `state: closed / open / gathered` is a shortcut (0 %, 100 %, 100 % italian). Pleats are sine waves; the fabric per wave stays constant (fullness), so gathered stacks fold deeper. A tab panel opens down to 14 % of its width; an Italian leading edge rises to 82 % of the height. | One number covers partly open; the two gather styles are what main curtains do. |
| 2026-11-18 | Battens | Position from the setting line and trim are the batten's placement y and z (`batten.update {y, trim}`), so attached curtains, borders and truss follow by the attachment tree. Numbers are unique like FIDs. The pipe runs along local x centred on the origin; the number sits in a circle at the stage-right (−x) end. | No second copy of the position to keep in sync. |
| 2026-11-18 | Wing sets | `wingset.create` makes a `wing_set` parent (draws nothing, keeps the values it was made with) with legs and borders as separate `masking` children. Borders hang on the batten within 400 mm of their wing (`hang_borders`, default on) and then leave the set. There is no `wingset.update`; pieces are edited one by one (`masking.update`). | Spec: generated in one go, edited afterwards. One parent per object, so a hung border belongs to its batten. |
| 2026-11-18 | Platforms | Origin at the centre of the footprint on its base; `height` is the deck top above it. Stacking is z: `platform.create {on}` puts it on another platform's deck. A system checks the height range and sets the understructure (Bütec legs, Nivoflex scissor). Plan: deck fill with diagonals and the top height (`+0.40`, world). | Plan convention for rostra; heights read in metres as on stage drawings. |
| 2026-11-18 | Proscenium | Origin at the centre of the opening on the setting line; the frame (pillars of `frame` width, header `frame` high) reaches upstage by `depth`. In plan the pillars are cut walls, the header dashed (above the cut), the iron line dash-dot with a label. | The setting line is the stage's y = 0 in German and English practice. |
| 2026-11-18 | Per-object plan style | `Object.style` (`object.set_style`): line class for every line of the symbol, labels on/off, detail low/high, hidden in plan. Unset fields follow the view. Batten numbers, platform heights and the iron label ignore the view's label switch (they are larger than FIDs; the canvas drops text below 7 pt anyway). | The hybrid model of the spec: parameters draw, the style restyles. |
| 2026-11-18 | Cloth colour in 3D | Meshes carry an optional sRGB `tint`; tintable materials (curtain, masking) take it, sent to the shader as bit 31 + RGB in the vertex material. The colour table grew to 16 slots (cut faces at 15). | Per-object colours without a material per colour. |
| 2026-11-18 | Detail levels beyond truss | `kinds::detail_size` gives the size a coarser level drops (truss width, pleat depth, pipe, 60 mm for platform legs and stands); the 3D view picks `Lod` by its screen size like truss, without the many-truss cap. Box level of a stand is its mast, not its bounding box. | Pleats and legs are noise at a distance; one rule for all. |
| 2026-11-18 | Stage tools | Toolbar: drawing tools, then stage objects (Run, Batten, Curtain, Portal, Wings, Platform, Support, Hoist, Ceiling); tool options on a second row. Shortcuts U run, B batten, C curtain, P platform, H hoist. Curtains drawn along a batten hang on it; platforms clicked onto a platform stack; fixtures clicked onto a batten hang under the pipe, onto a support stand on top. | Sixteen tools need a second row for their options; attach where the user clicks, as for truss. |
| 2026-11-18 | Hoists | `hoist` is a rigging point: origin at the hook, body above, a chain stub up. Things hang from it by attachment; its load is its subtree. | Needed for "load per hoist point"; chain length to the roof is unknown. |
| 2026-11-18 | Sheets in core | Sheets, viewports, label templates and title blocks are document data in core (`sheet.rs`), so they undo, save and are scriptable like everything else; drawing them lives in `stagecraft-sheet`. | Every action is a command; the PDF code must not leak into core. |
| 2026-11-18 | Export hook | `sheet.export_pdf`/`sheet.export_svg` are core commands that call a `SheetExporter` installed by `stagecraft_sheet::install()` (app main, `Studio::new`). Without one they fail with a clear message. | Core cannot depend on the sheet crate (it depends on core); the command still shows in every registry listing and works headless via `stagecraft exec … --file`. |
| 2026-11-18 | Paper coordinates | Paper mm from the lower left, y up. A viewport is `position` (centre on paper) + `scale` (denominator) + `crop` (model mm in view coordinates, `None` = fit with 2 % margin). Resizing a viewport changes the crop, never the scale. | Same as Vectorworks: scale is a drawing decision, the crop follows layout. |
| 2026-11-18 | Label anchors | Field anchors are fixture-local model mm (y towards the lens); text size and the anchor gap are paper mm. A non-zero anchor pushes the text box outwards along the anchor direction until its near side is `gap` beyond the anchor; fields on the same anchor stack outwards; a `[0,0]` anchor centres the field on the fixture. | Anchors follow the symbol's geometry at every scale while text stays a readable paper size. |
| 2026-11-18 | Label rotation | Anchored-upright transforms anchors through the fixture's world transform projected to plan (a turned-over fixture mirrors the anchors, not the text); sheet-fixed uses the unrotated layout; follow turns the text with the fixture's local x and folds the angle into (−90°, 90°]. Text is never mirrored in any mode. | The user's main Vectorworks pain: labels that rotate or mirror with the fixture. |
| 2026-11-18 | Label collisions | Greedy per field: dragged labels first (as a whole), then fields centred on their fixtures (FIDs), then the rest top-left to bottom-right; each tries its template spot, then rings of 1–21 mm displacement, first collision-free wins, else least overlap. Obstacles: placed fields, other fixtures' footprints, plan text. Moves over 3 mm get a leader. | Moving whole labels pulled FIDs off their fixtures; per field keeps FIDs on the symbol. |
| 2026-11-18 | Manual label offsets | Stored per viewport per fixture (`label_offsets`, paper mm), set by `label.move` (absolute or relative), cleared by `viewport.update {reset_labels}`. | Spec: labels can be dragged per viewport. |
| 2026-11-18 | Line weights | Default pens (ISO 128): thin 0.18, medium 0.35, thick 0.5, hidden 0.25 dashed 1.6/0.8, centre 0.18 dash-dot, cut 0.7; elevation edges thin; section hatch 0.13 at 45°, 1.2 mm. Per viewport `line_weights` overrides by class. Per-tag weights are not done yet. | Matches common theatre drawing practice; classes come from geom. |
| 2026-11-18 | Elevation/section fallback | Until `stagecraft-hlr` is wired in, `FallbackSource` draws feature edges (boundary, silhouette, creases over 25°) of faces facing the viewer, clipped to the kept side of a section plane, plus hatched cut faces from `geom::section`. No occlusion between objects. Cloth draws at `Lod::Box` above 1:25 (pleat outlines are a wall of lines). View axes match `stagecraft-hlr::View` (`right = dir × up`). | Something useful now; the trait makes the swap a one-line change in `default_source()`. |
| 2026-11-18 | Rendered viewports | Size = crop / scale, or 180 × 120 mm without a crop. Images come from a raster cache (`set_raster`); the GUI does not render into it yet, so PDF shows a labelled placeholder box. | Offscreen 3D readback is its own piece of work; the hook is in place. |
| 2026-11-18 | Title block | Generic 180 × 50 mm block at the lower right inside a 10 mm frame (0.7 mm). Placeholders {project} {venue} {drawn_by} {date} {scale} {revision} {sheet_name} {sheet_number} {company} {paper}; {scale} lists the distinct scales of vector viewports. Left-aligned text shrinks to fit before the next vertical line. Logo: PNG/JPEG stored base64 in `meta.logo` (`doc.set_meta {logo_file}`). `meta.date` is free text; core has no clock. | User: generic, filled from document settings. |
| 2026-11-18 | Legend and fixture list | The legend (above the title block) counts fixtures shown in the sheet's plan viewports by type (GDTF name, else "Generic fixture"). The fixture list is a viewport kind (FID, name, type, mode, address, gel, circuit, note), sorted by FID. | Types come with block 5; counting by GDTF file name already works. |
| 2026-11-18 | Fixture attributes | Gel, circuit, focus, note are free `Object.attrs` (`object.set_attrs`), not fixture fields; labels show any key with `attr:<key>`. | Spec: "any attribute"; no schema change needed for new keys. |
| 2026-11-18 | Plan labels | The plan canvas draws labels with a template chosen per view (`ui.set_label_template`, UI state), at 4.5 screen points per paper mm, hidden when a fixture is under 5 points wide. | Spec: labels in the plan too, template per view. |
| 2026-11-18 | Fonts | Roboto moved to `assets/fonts/` (shared by GUI and PDF); PDF embeds subsets via krilla. | One copy of the font. |
| 2026-11-18 | GDTF: Units in types | Parsed types keep the XML units (metres, degrees, W, kg) and say so in field names (`length_m`, `beam_angle_deg`). Meshes, instances and silhouettes are in mm. | The data mirrors the file; everything that feeds geometry uses StageCraft's mm. |
| 2026-11-18 | GDTF: Axes | GDTF axes everywhere: x right, y away from the viewer, z up, fixture hanging, beams along −z. | This is the MVR fixture-local frame, so callers place meshes with the MVR matrix alone. |
| 2026-11-18 | GDTF: Matrices | Rows as written, translation in the 4th column (spec). If the 4th column is zero and the 4th row carries a translation, it is moved (old exporters). 3-row and 3×3 matrices are padded with identity. Unreadable → identity + warning. | Tolerance; the spec text is explicit about column-major meaning. |
| 2026-11-18 | GDTF: Tolerance | Only a missing/broken zip, a missing `description.xml`, malformed XML or a missing `<FixtureType>` fail. Everything else is a `Warning` (context + message). Trailing NUL bytes and junk after `</GDTF>` are cut (six real files had NULs). Decimal commas are accepted. Model and geometry names match ignoring surrounding whitespace (Astera writes `"Pixel 16 pix "`). | Real manufacturer files are messy; parse what we can. |
| 2026-11-18 | GDTF: Weight / leg height | `0` (the spec default) reads as `None`. | A zero weight would silently vanish from load sums. |
| 2026-11-18 | GDTF: Power | `power_w()`: sum of `<PowerConsumption>` if present, else sum of beam `PowerConsumption` **attributes actually written** (the spec default 1000 W per beam is not counted). | Avoid inventing 1000 W for every LED pixel. |
| 2026-11-18 | GDTF: Footprint | Per break: the highest slot used. Mode root = the mode's `Geometry`; channels on geometries in that tree keep their offsets; channels on a template are repeated per `GeometryReference` at `DMXOffset + Offset − 1`; `DMXBreak="Overwrite"` takes the reference's last `<Break>`; a missing matching `<Break>` means offset 1 (warning). Channels on geometries outside the mode tree are placed as written (warning). | Spec text plus what GDTF Builder produces. Verified: footprints equal GDTF Share's reported footprints for all 16 modes of 5 downloads, and datasheets for Spikie, Esprite, LEDWash 600, T-PIX 12. |
| 2026-11-18 | GDTF: Nested references | References inside a template are expanded for meshes and names, but their offsets are not added to the outer reference's. | GDTF defines no nested DMX offsets. |
| 2026-11-18 | GDTF: Reference instances | An instance takes the reference's name, position and (optional) model; the template's own `Position` is ignored; its kind (e.g. `Beam`) is kept. | Spec: the reference describes the instance; templates are usually at identity. |
| 2026-11-18 | GDTF: Mesh file choice | Lookup order glTF then 3DS (`gltf`, `3ds`; for `Lod::Low/High` first the `_low`/`_high` folders). Case-insensitive; a `File` with extension is accepted. Missing or broken file → primitive + warning. | Spec prefers glTF. |
| 2026-11-18 | GDTF: glTF axes | GLB is read as y-up and turned to z-up: (x, y, z) → (x, −z, y). Node transforms applied. Checked on Robe and Vectorworks files: extents then match the model dimensions. | glTF convention; GDTF Builder exports this way. |
| 2026-11-18 | GDTF: Wrong up axis | If the model dimensions fit the other up-axis reading clearly better (shape error < ½ and > 0.3), the mesh is turned and a warning added. | Cheap guard against exporters that ignore the glTF convention. Never triggered on the real files. |
| 2026-11-18 | GDTF: Scaling | Scaled about the mesh origin (not recentred) to Length × Width × Height. Axis with dimension 0: mean scale of the others. No dimensions: glTF read as metres, 3DS as mm (metres if smaller than 10 units). | Spec rule; origin is the suspension point. |
| 2026-11-18 | GDTF: Wrong dimensions | If one axis already matches the dimensions in m or mm (±1 %) but another would stretch by more than 25 %, the mesh keeps its proportions at that unit (warning). | Vectorworks "Custom@" files write Width = Height = diagonal; strict scaling made a Robe T1 718 mm deep. Now 400 × 294 × 736 mm, matching the datasheet. |
| 2026-11-18 | GDTF: Primitives | Generated (box, cylinder, ellipsoid, yoke U, scanner, conventional), not the spec's reference 3DS meshes, which carry no licence. Placement copied from those meshes: GDTF 1.0 types (`Base`, `Yoke`, `Head`, `Scanner`, `Conventional`) and `Cube`/`Cylinder`/`Sphere`/`Pigtail` centred; `Base1_1`, `Scanner1_1`, `Conventional1_1` hang below the origin. `Conventional` (1.0) lies along y, `Conventional1_1` along z. `Undefined` without a file → box. | Licence; same bounding boxes as the references. |
| 2026-11-18 | GDTF: Normals | glTF normals kept when every primitive has them; otherwise flat normals (vertices unwelded). 3DS always flat (smoothing groups ignored). | Simple and correct shading for low-poly fixture meshes. |
| 2026-11-18 | GDTF: Silhouette | Convex hull per part plus one for the whole fixture, top view, mm, CCW. | Per-part hulls keep yoke arms and pixel rings readable; a true union outline can come later. |
| 2026-11-18 | GDTF: SVG | Raw bytes per model and view (`models/svg`, `svg_side`, `svg_front`); `plan_svgs()` lists top views with each instance's transform. No SVG composition here. | Plan symbols are assembled by the plan code. |
| 2026-11-18 | GDTF: Share HTTP | `ureq` 3 (blocking, rustls), cookie jar in the agent, 120 s timeout, 512 MB body limit. Errors from `downloadFile.php` arrive as JSON with HTTP 200, so a download must start with `PK`. | Small dependency; the app calls it from a worker thread. |
| 2026-11-18 | GDTF: Share cache | `<cache>/list.json` (raw answer, age from file mtime), `<cache>/files/<rid>.gdtf` (never stale: a rid is one revision). A failed refresh falls back to a stale list. | Offline use; rids are immutable. |
| 2026-11-18 | GDTF: Share list parsing | Field by field from `serde_json::Value`, numbers accepted as strings and vice versa; entries without `rid` dropped. | The live list mixes types (`rating` is a string). |
| 2026-11-18 | GDTF: Keychain | Feature `keychain` (macOS): account from an attribute search via `security-framework`; the secret via `/usr/bin/security find-generic-password -w` (captured, never echoed), the framework read only as fallback. | Reading the secret through the framework opens an "allow access" dialog for every newly built binary, which hangs unattended runs; `security` is on the item's access list. |
| 2026-11-18 | GDTF: Live test | `share_live` is `#[ignore]` and downloads into `testdata/private/gdtf/` (cache in `.share-cache/` there). | Network and credentials.
